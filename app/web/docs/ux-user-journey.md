# UX: пользовательский путь Career Quest

## Главная UX-идея

Пользователь должен сразу понять:

1. где он находится в карьерном пути;
2. что сейчас важнее всего развить;
3. какой следующий шаг нужно сделать;
4. почему система рекомендует именно его.

Главный CTA приложения: **«Начать следующий шаг»**.

Не следует начинать с большого каталога активностей или перегруженного дашборда.

## Вход в приложение

### Реальный продукт

- вход через корпоративный аккаунт;
- выбор языка: русский, казахский или английский;
- автоматическое определение роли: сотрудник или HR;
- сотрудник не выбирает роль вручную.

### MVP для хакатона

- выбор сотрудника из списка;
- отдельная кнопка «Войти как HR»;
- быстрый доступ к проверочным профилям жюри.

Жюри должно иметь возможность открыть нужный сценарий за 10–15 секунд.

## Путь сотрудника

```text
Вход
  ↓
Главная
  ↓
Текущее положение и skill gaps
  ↓
Рекомендованный следующий шаг
  ↓
Объяснение рекомендации
  ↓
Выполнение активности
  ↓
Обновление прогресса
```

## Главная страница сотрудника

### Самое важное

1. Приветствие и текущий статус:

   > Вы — Middle Backend Engineer. Следующий уровень — Senior.

2. Прогресс к следующему грейду:

   > Готовность к Senior: 68%

3. Блок «Ваш следующий шаг»:

   - одна главная рекомендация;
   - до двух альтернатив;
   - название активности;
   - закрываемый навык;
   - текущий и требуемый уровень;
   - ожидаемый прирост;
   - длительность и формат;
   - кнопка «Подробнее» или «Начать».

4. Объяснение рекомендации:

   > System Design — критичный навык для Senior. Сейчас уровень 2 из 4. Активность может повысить уровень до 3.

### Средняя важность

- топ-3 skill gaps;
- карьерная траектория `Junior → Middle → Senior → Lead`;
- последние активности и их статусы;
- текущая карьерная цель.

### Низкая важность

Эти элементы не должны мешать основному сценарию:

- полная история активностей;
- второстепенная статистика;
- внутренняя валюта;
- рейтинги и достижения;
- социальные механики;
- расширенные фильтры.

Их следует вынести на отдельные страницы или скрыть в раскрывающихся блоках.

## Страница рекомендации

Пользователь должен получить ответы на три вопроса.

### Почему это нужно?

- какой навык проседает;
- насколько он важен для следующего грейда;
- как история участия повлияла на рекомендацию.

### Что это даст?

- какой навык развивается;
- на сколько уровней он может вырасти;
- как изменится готовность к следующему грейду.

### Что нужно сделать?

- формат и длительность;
- ближайшая дата или доступность в любое время;
- prerequisites;
- кнопка «Начать» или «Записаться».

Пример:

```text
System Design Workshop

Почему рекомендуем:
Критичный навык для Senior Backend Engineer.
Текущий уровень: 2 / 5
Требуемый уровень: 4 / 5
Ожидаемый прирост: +1

Формат: online
Длительность: 3 часа
Ближайшая дата: 12 октября

[Начать активность]
```

## Завершение активности

После выполнения нужно показать не только уведомление, но и результат:

```text
До:
System Design: 2/5
Готовность к Senior: 68%

После:
System Design: 3/5
Готовность к Senior: 76%
Закрыто 1 из 4 ключевых разрывов
```

После результата система должна предложить следующий шаг.

Основной цикл:

```text
Рекомендация → Действие → Результат → Следующий шаг
```

## Путь HR

HR должен видеть отдельный дашборд, а не интерфейс сотрудника.

### Самое важное

- наиболее проседающие навыки;
- роли или отделы с наибольшими разрывами;
- количество сотрудников без следующего шага;
- общий уровень участия в развитии.

### Средняя важность

- таблица сотрудников;
- фильтры по отделу, роли и грейду;
- статистика по активностям;
- сотрудники с большим числом пропусков или отказов.

### Низкая важность

- подробная история конкретного сотрудника;
- оценки мероприятий;
- расширенные выгрузки;
- конструктор новых активностей.

Пример HR-виджета:

```text
Навык с наибольшим дефицитом
Leadership — 47 сотрудников

Участие в развитии
Завершено — 79%
Пропущено — 7%
Брошено — 6%
Отказались — 4%

Сотрудники без рекомендации
12
```

## Приоритеты реализации

### P0 — обязательно

- вход и определение роли;
- профиль сотрудника;
- текущий и следующий грейд;
- skill gaps;
- одна главная AI-рекомендация;
- объяснение рекомендации;
- выполнение активности;
- обновление прогресса;
- базовый HR-дашборд;
- состояния загрузки, ошибки и отсутствие рекомендации.

### P1 — желательно

- 2–3 альтернативные рекомендации;
- HR-фильтры;
- история активностей;
- карьерная timeline;
- мультиязычность;
- загрузка дополнительных JSON/CSV;
- просмотр деталей навыка.

### P2 — позже

- внутренняя валюта;
- награды;
- признание коллег;
- менторские механики;
- персональные челленджи;
- прогноз риска оттока;
- календарь и мессенджеры;
- мобильная адаптация.

## Демонстрационный сценарий

```text
1. Войти как сотрудник
2. Увидеть грейд и прогресс
3. Открыть главную рекомендацию
4. Понять объяснение через skill gap и требования Senior
5. Выполнить активность
6. Увидеть изменение навыка и прогресса
7. Перейти в HR-view
8. Увидеть агрегированные проблемы по навыкам и участию
```

## Основной принцип

На каждом экране должен быть один очевидный следующий шаг. Остальная информация раскрывается по запросу и не конкурирует с главным действием пользователя.
