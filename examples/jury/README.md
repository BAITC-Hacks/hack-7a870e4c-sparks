# Синтетический пример импорта жюри

Два вымышленных профиля и шесть записей участия, подготовленные AI-агентом для проверки импорта. Это дополнительные тестовые данные команды, а не материалы Организатора и не реальные сотрудники. Формат соответствует исходному датасету, дата среза — `2026-10-01`. Идентификаторы `JURY_BACKEND_ALPHA` и `JURY_QA_BETA` отсутствуют в исходных 200 профилях; ссылки на руководителей `E0050` и `E0063` существуют в исходном наборе.

1. Войдите в приложение с выданными отдельно данными доступа HR.
2. В разделе импорта выберите `employees.json` и `activity_history.csv` из этой папки и выполните импорт.
3. Ожидаемый результат: приняты 2 профиля и 6 строк истории. На неизменённой исходной базе станет 202 сотрудника и 2749 записей истории. Повторный импорт этих файлов обновляет те же записи по ID и не добавляет дубликатов.
4. Найдите новые профили в списке сотрудников HR и откройте каждый профиль; запросите следующие шаги развития.

| Профиль | Что проверяет |
| --- | --- |
| `JURY_BACKEND_ALPHA` | Junior → Middle, начатый `EV_005`, завершённый после оценки `EV_012`: Python становится 2 вместо исходного 1, но уже завершённый курс не рекомендуют повторно. Два ежегодных завершения обязательного `EV_001` остаются в истории и не попадают в рекомендации. |
| `JURY_QA_BETA` | Middle → Senior, дефицит Test Automation 3 → 4 и непокрытый каталогом Test Design 2 → 4. `EV_018` допустим и сокращает первый разрыв. Завершённый до оценки `EV_019` не повышает повторно API Testing и Load Testing. После завершения `EV_018` остаётся объяснённое отсутствие следующего шага из-за Test Design. |

Допустимые активности определяются сервером. Таблица описывает проверяемые свойства данных и фильтрации; конкретный выбор LLM заранее не фиксируется. При отсутствии настроенного AI-сервиса приложение явно показывает расчётный режим.

Импорт доступен только HR. Профили доступны HR сразу, а данные входа новых сотрудников выдаются отдельно через административную CLI-команду, описанную в основном README. Импорт не передаёт пароль и роль пользователя. Используйте только синтетические данные в рамках хакатона.
