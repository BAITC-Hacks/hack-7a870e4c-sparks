# Career Quest Agent

Сервис на FastAPI для карьерных консультаций. Elysia API передаёт профиль сотрудника, навыки, требования к ролям, мероприятия и историю участия при каждом запросе. Агент не читает локальные файлы `data/` и не хранит состояние диалога.

## Запуск вместе с API

Из корня репозитория:

```bash
./init.sh --no-open
```

Нужны Docker с Compose и `openssl`. Скрипт создаёт недостающие локальные пароли в корневом `.env`, собирает и запускает PostgreSQL, FastAPI-агент и Elysia API, затем ждёт их готовности. Swagger API: `http://localhost:3001/api/docs` (порт меняется через `API_PORT`). Существующие настройки и данные PostgreSQL сохраняются. Команда `docker compose down` останавливает сервисы и сохраняет данные.

Compose передаёт `OPENAI_API_KEY` и `OPENAI_MODEL` только Python-агенту. API обращается к нему по `AGENT_URL=http://agent:8000` во внутренней сети Docker; порт агента наружу не публикуется. API запускается после успешных healthcheck PostgreSQL и агента. Агент работает и без ключа, возвращая рекомендации по правилам. Наличие ключа не подтверждает доступ к модели.

Добавьте `OPENAI_API_KEY` и при необходимости `OPENAI_MODEL` в корневой `.env`. Существующее имя `OPENAI_KEY` тоже работает. В Compose модель по умолчанию — `gpt-6-astra`. Значения для примера находятся в корневом [.env.example](../../.env.example). После изменения ключа или модели повторите команду запуска.

Значение `OPENAI_MODEL` из `.env` перекрывает значение по умолчанию в Compose. После изменения модели нужно пересоздать агент: `docker compose up -d --no-deps --wait agent`. После изменения его кода добавьте `--build`.

## Локальный запуск агента

Из корня репозитория:

```bash
python3 -m venv venv
venv/bin/pip install -r apps/agent/requirements.txt
OPENAI_MODEL=gpt-6-astra venv/bin/uvicorn agent.main:app --app-dir apps --reload --host 127.0.0.1 --port 8000
```

Агент загружает корневой `.env`. Для локально запущенного Elysia API задайте `AGENT_URL=http://127.0.0.1:8000` в его окружении. `GET /health` проверяет работу сервиса, `/docs` показывает OpenAPI. Отдельный процесс агента нужен до запуска API.

## Отдельный Docker-контейнер

Из корня репозитория собирайте образ с контекстом **только** `apps/agent`:

```bash
docker build -t career-agent apps/agent
docker run --rm -p 127.0.0.1:8000:8000 --env-file .env -e OPENAI_MODEL=gpt-6-astra career-agent
```

Сервис слушает порт `8000` внутри контейнера. Корневой `.env` используется только при запуске и не попадает в образ. Для обращения из другого контейнера используйте имя сервиса или контейнера в общей сети Docker, а не `localhost`.

## Внутренний запрос от Elysia API

Маршруты ниже принадлежат FastAPI-агенту. Elysia API выполняет авторизацию и собирает контекст из PostgreSQL; браузер обращается к публичным маршрутам API, а не к агенту напрямую.

`POST /api/v1/advisor/chat` принимает вопрос, контекст сотрудника и необязательную историю диалога:

```json
{
  "message": "Каких навыков мне не хватает и что пройти?",
  "conversation_history": [],
  "context": {
    "as_of_date": "2026-10-01",
    "employee": {
      "employee_id": "E0001",
      "full_name": "Сотрудник",
      "role": "Backend Engineer",
      "grade": "Junior",
      "skills": {"SK_PYTHON": 2},
      "career_goal": {"target_role": "Backend Engineer", "target_grade": "Middle"},
      "last_review_date": "2026-09-11",
      "preferred_language": "ru"
    },
    "skills": [
      {"skill_id": "SK_PYTHON", "name": "Python", "type": "hard"}
    ],
    "role_profiles": [
      {
        "role": "Backend Engineer",
        "grade": "Middle",
        "required_skills": {"SK_PYTHON": 3},
        "critical_skills": ["SK_PYTHON"]
      }
    ],
    "events": [
      {
        "event_id": "EV_101",
        "title": "Python Practice",
        "description": "Практический курс по Python",
        "type": "course",
        "format": "self_paced",
        "duration_hours": 4,
        "mandatory": false,
        "target_roles": ["Backend Engineer"],
        "target_grades": ["Junior", "Middle"],
        "develops_skills": [{"skill_id": "SK_PYTHON", "gain": 1, "max_level": 3}],
        "prerequisites": {},
        "upcoming_sessions": []
      }
    ],
    "activity_history": []
  }
}
```

Ответ чата содержит `employee_id`, `reply`, `plan` и `recommendations` — полный результат подбора в формате ниже. `plan.recommendations` совпадает со списком из результата подбора. Для следующего сообщения Elysia API передаёт `conversation_history` с элементами `{ "role": "user" | "assistant", "content": "..." }`; используются до 12 последних реплик.

Для загрузки карточек без чата используйте `POST /api/v1/advisor/recommendations` с телом `{ "context": { ... } }`. Его ответ соответствует типу `Recommendations` из [контрактов TypeScript](../api/src/contracts.ts):

| Поле | Значение |
|---|---|
| `mode` | `ai` при принятом выборе модели, `rules` при расчёте по правилам |
| `model` | Название использованной модели или `null` |
| `message` | Ответ консультанта или сообщение о подборе по правилам |
| `recommendations` | 1–3 карточки; пустой список, если допустимых шагов нет |
| `generated_at` | Время формирования в UTC |
| `duration_ms` | Время обработки запроса на подбор |

Карточка соответствует `Recommendation`: `event`, `score`, `factors`, `next_session`, `gains`, `in_progress`, `explanation`. В `factors` всегда четыре категории: `grade`, `gap`, `history`, `target`. Объяснение собирается из проверенных фактов. Модель выбирает ID и порядок шагов, а уровни навыков, доступность и факторы вычисляет Python. В версии 0.2 поля `event_id` и `title` карточки перенесены в `event`, общее `reason` заменено на `factors` и `explanation`.

Для обычного подбора OpenAI возвращает только `event_ids` по схеме `RecommendationSelection` с лимитом 512 выходных токенов. Генерировать повторное текстовое объяснение не требуется: факторы и пояснения карточек уже рассчитаны приложением. Чат сохраняет схему `ModelDecision` с полем `reply` и лимитом 1600 токенов. Для `gpt-6-astra` явно задан `reasoning.effort=low` ([параметры модели](https://developers.openai.com/api/docs/models/gpt-6-astra)). Общий таймаут попытки остаётся 8 секунд; при таймауте или невалидном выборе включается расчётный режим.

Пустой Request Payload у `POST /api/employees/E0005/recommendations` на порту API — нормальный контракт. Elysia принимает `{}` или отсутствие тела, проверяет сессию и отправляет агенту отдельный JSON `{context: ...}` с профилем E0005, только его историей, навыками, требованиями ролей и каталогом. В браузере виден первый запрос, а второй выполняется между серверами.

`POST /api/v1/advisor/plan` принимает тот же `context` и быстро возвращает план по правилам без OpenAI. Он подходит для первичной отрисовки профиля. AI-подбор можно загрузить отдельным запросом. Ошибки схемы и ссылок между данными возвращают `422`; отсутствие ключа, сбой OpenAI, отказ модели или невалидный выбор возвращают `200` с `mode: "rules"` и рабочими карточками.

Elysia API собирает контекст из своего набора: `employee` — выбранный сотрудник, `activity_history` — его записи из `Dataset.history`, остальные каталоги — `skills`, `role_profiles`, `events`. Передавайте также мероприятия из истории, даже если они больше не доступны для записи: они нужны для анализа участия. Пустые ячейки CSV преобразуйте в `null`. ID новых проверочных профилей не ограничены диапазоном исходного набора. Неизвестные ссылки, дубликаты ID и уровни вне 0–5 отклоняются.

## Как выбираются шаги

Сначала проверяются текущая роль и грейд, все prerequisites, даты, обязательность и история. Уже начатое и завершённое обучение исключается; клуб `EV_036` допускает повторы по правилу датасета. Цель по умолчанию — следующий грейд текущей роли, с `goal_source: "next_grade"`. Для Lead без цели автоматического повышения нет.

Первым выбирается мероприятие, которое сокращает критический дефицит, если такое доступно. Оценка кандидата складывается из:

- 1000 баллов за сокращение хотя бы одного критического разрыва;
- 100 × сумму закрываемых долей критических дефицитов и 40 × сумму долей всех дефицитов;
- до 6 баллов за завершённые похожие активности;
- штрафа за неявки, отказы и прекращение: 25 за попытку данного мероприятия и 10 за попытку другого мероприятия того же формата с общими навыками, суммарно не больше 120;
- поправки за длительность `min(10, duration_hours / 8)`.

Это явная политика ранжирования прототипа, а не вероятность успешного завершения или решение о повышении. История не запрещает повторную попытку и не трактуется как оценка мотивации сотрудника. Все использованные количества показываются в факторах.

OpenAI получает до 12 допустимых кандидатов с рассчитанными факторами и выбирает 1–3 шага через [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Python проверяет ID, отсутствие повторов, критический приоритет первого шага и пользу каждого следующего шага после предыдущих. Числа и текст карточек не принимаются от модели. Таймаут всей попытки — 8 секунд, повторных API-запросов нет; затем используется результат по правилам. Это ограничивает ожидание AI, но фактическую задержку развёрнутой системы нужно измерять отдельно.

Модель получает карьерные факты, до 24 последних записей участия и историю переписки. Имя и ID сотрудника из профиля исключаются; текст переписки передаётся как получен. Запрос выполняется с `store=False`. Agent не имеет своей базы сотрудников и не изменяет данные Elysia API.

## Прогресс после выполнения

Elysia API сохраняет `status: "completed"`, `completion_pct: 100` и `completed_at` в записи участия и повторно отправляет контекст. Повторное нажатие кнопки должно обновлять ту же запись `record_id`. `employee.skills` остаётся снимком последней оценки, а `effective_skills` — вычисленным результатом; не прибавляйте эффект одновременно к обоим.

В расчёт входят только завершения после `last_review_date` и не позже `as_of_date`. `completed_at` принимается как ISO-дата или ISO-время; сравнение с оценкой выполняется по дням. Записи без точной даты завершения и с неизвестной датой оценки не начисляют прирост. Предупреждения об этом находятся в `plan.warnings`. Для исторического CSV точный момент завершения восстановить нельзя.

`readiness` — процент покрытия требований: `100 × sum(min(level, required)) / sum(required)`. Это не вероятность повышения. `projected_readiness`, `projected_skills` и `trajectory` показывают результат последовательного выполнения выбранных шагов. Прирост ограничен `gain` и `max_level` и никогда не снижает уже достигнутый уровень. Фактическое сохранение выполнения, права сотрудник/HR и агрегаты HR остаются в Elysia API.

## Проверка

```bash
PYTHONPATH=apps venv/bin/python -m unittest discover -s apps/agent/tests -v
```

Тесты покрывают ловушку из ТЗ (критический навык против короткой активности по слабому навыку), пропуски и отказы, ограничения допуска, прирост после выполнения, проверку ответа модели, таймаут и REST-контракт. OpenAI подменяется в тестах; реальных API-вызовов нет.
