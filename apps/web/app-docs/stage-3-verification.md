# Стадия 3: рекомендации, план и советник

Реализована 23 сентября 2026 года по [плану API-интеграции](./api-implementation-stages.md).

## Реализация

- `/employee`: профиль → основной следующий шаг → не более двух альтернатив →
  навыки → последние три записи истории. Подбор выполняется при загрузке,
  смене цели и явном обновлении; фокус окна не запускает новый POST.
- Карточки показывают `mode`, `message`, имя модели только для `ai`, время
  подбора, формат, длительность, сессию, категории факторов и серверный прогноз
  навыков. `rules` явно обозначен как расчёт без AI.
- `/employee/activity/[activityId]`: описание, объяснение, прирост, аудитория,
  начальные навыки, доступность. Профиль берётся из сессии, а не из URL.
  Уровни prerequisites проверяются в mapper. Дата доступности берётся из
  `catalog.as_of_date`. Выполненное занятие блокируется; для EV_036 учитывается
  разрешённый повтор в другой расчётный день. Обязательные занятия исключены
  из рекомендаций.
- `/employee/career`: текущая позиция и цель, текущие и прогнозные навыки и
  покрытие требований, до трёх шагов, непокрытые навыки, обязательные задачи,
  предупреждения, дата оценки и пояснение учтённых завершений. `null` не
  превращается в 0%. При 503 сохраняется уже полученный план с предупреждением.
- Советник отправляет только `message` (1–3000 символов) и последние 20 реплик.
  Контекст диалога хранится в состоянии экрана и сбрасывается при смене
  сотрудника/новом диалоге. Ответ инвалидирует план и рекомендации этого
  сотрудника; ошибка сохраняет черновик. Автоматический повтор POST отключён.
- Новые защищённые запросы и мутации помечены `requiresSession`. Их 401
  очищает закрытые данные и переводит на локализованный вход. Публичные ошибки
  не завершают сессию. При 403 данные закрываются и отображается ошибка доступа.

Новых зависимостей нет. Используются существующие Next.js 16, React 19,
TanStack Query, Orval/axios, next-intl и shadcn/ui. Generated-клиент не
редактировался. Удалён неиспользуемый редактор пользователя из Petstore-шаблона,
ссылавшийся на отсутствующую в Career Quest операцию `updateUser` и мешавший
TypeScript/build. Исправлены пространство переводов профиля и отсутствующие
тексты общего каркаса.

## Проверки

Из `apps/web`:

```bash
pnpm exec tsc --noEmit
pnpm test:run
pnpm lint:deps
pnpm build
pnpm exec playwright test tests/e2e/stage3.spec.ts --project chromium
```

Если frontend уже запущен по другому адресу, можно явно указать его. В этом
режиме Playwright не запускает и не останавливает сервер:

```bash
STAGE3_BASE_URL=http://127.0.0.1:3000 pnpm exec playwright test tests/e2e/stage3.spec.ts --project chromium
```

Прошли 108 unit/component tests, 15 Chromium-сценариев, TypeScript,
dependency-cruiser и production build. Для изменённых TypeScript/TSX/JSON-файлов
прошёл отдельный Biome check. Просмотрены desktop RU и mobile KK; браузерная
проверка также проверяет отсутствие горизонтального переполнения.

E2E подменяет HTTP-ответы **только в тестах**. Проверяет рекомендации и детали с
перезагрузкой, различие AI/rules, пустой ответ, retry, факторы и доступность,
план/прогноз, mandatory tasks, 503 с сохранением плана, советника и инвалидацию,
ограничение HR и 401. Production hooks не подставляют fixtures при сбоях.

Общие `pnpm lint` и `pnpm lint:unused` не проходят из-за оставшихся замечаний
шаблона: форматирование/доступность старых общих компонентов и неиспользуемые
компоненты, файлы и зависимости. Эти проверки запускались; их результат не
обозначен успешным.

## Границы стадии

- В API нет получения произвольного мероприятия по ID. Прямая ссылка работает
  для шага из текущих рекомендаций или плана; иначе показывается «не найден».
- `/plan` не возвращает `mode` и `model`; экран плана не приписывает ему
  использование конкретной AI-модели. У советника режим берётся из
  `response.recommendations`.
- Завершение активности и before/after — стадия 4. HR-данные и импорт —
  стадии 5–6. Запуск/прохождение занятий не имитируются.
- Контрактные тесты не подтверждают живой OpenAI, CORS/proxy-конфигурацию,
  развёртывание и задержку ответа на реальной инфраструктуре. Для сквозной
  проверки нужен доступный API с cookie-сессией и корректным browser origin.
