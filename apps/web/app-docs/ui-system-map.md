# Career Quest — UI-карта веб-приложения

## 1. Визуальное направление

Career Quest должен восприниматься как спокойный корпоративный продукт для развития сотрудника: надёжный, ясный и персональный.

Связь с банковской средой передаётся ненавязчиво через:

- глубокий зелёный как основной цвет действия и доверия;
- тёплый жёлтый как редкий акцент цели и прогресса;
- светлый тёплый фон вместо холодного dashboard-blue;
- строгую сетку, тонкие разделители и аккуратную типографику.

Не использовать логотип, прямые брендовые упоминания или визуальное копирование фирменных материалов.

Основной принцип: **содержание и следующий шаг важнее декоративной карточки**.

## 2. Цветовые токены

### Primitive tokens

| Token | Значение | Назначение |
|---|---|---|
| `green-950` | `#123C34` | заголовки, основной контраст, primary button |
| `green-700` | `#008F73` | действия, ссылки, положительная динамика |
| `green-100` | `#DDF1E9` | мягкий фон завершённых состояний |
| `yellow-400` | `#F4C64E` | цель, текущий этап, точечный акцент |
| `yellow-100` | `#FFF4D6` | мягкое предупреждение и критичный skill gap |
| `cream-50` | `#F7F5EE` | основной фон приложения |
| `surface` | `#FFFFFF` | контентные поверхности и формы |
| `border` | `#D8E2DC` | разделители и границы |
| `text-secondary` | `#6C7D75` | вторичный текст |
| `text-muted` | `#52675E` | пояснения и метаинформация |
| `danger` | `#B94A48` | ошибки и просрочки |

### Semantic tokens

В компонентах использовать смысловые токены, а не значения цветов напрямую:

```css
--background: var(--cream-50);
--foreground: var(--green-950);
--primary: var(--green-950);
--primary-foreground: #ffffff;
--accent: var(--green-700);
--accent-foreground: #ffffff;
--muted: var(--green-100);
--muted-foreground: var(--text-secondary);
--border: var(--border);
--ring: var(--green-700);
--success: var(--green-700);
--warning: var(--yellow-400);
--destructive: var(--danger);
```

Для новых компонентов использовать `bg-background`, `text-foreground`, `bg-primary`, `text-muted-foreground`, `border-border` и варианты shadcn, а не `bg-[#...]`.

## 3. Типографика

Предпочтительный шрифт: `Inter`, `Manrope` или системный sans-serif fallback.

| Роль | Размер | Line height | Вес |
|---|---:|---:|---:|
| Page title | 36px | 44px | 600 |
| Section title | 20px | 28px | 600 |
| Card/row title | 16px | 24px | 600 |
| Body | 14–16px | 22–24px | 400 |
| Metadata | 12–13px | 18px | 400 |
| Eyebrow/label | 11–12px | 16px | 600 |

Правила:

- заголовки — плотные и короткие;
- объяснение рекомендации — обычный текст, не бейдж;
- uppercase использовать только для маленьких label/eyebrow;
- не использовать много разных размеров на одном экране;
- текст должен сохранять читаемость при 200% zoom.

## 4. Отступы и сетка

Базовый шаг — 4px, основной рабочий ритм — 8px.

```text
space-1   4px
space-2   8px
space-3   12px
space-4   16px
space-5   20px
space-6   24px
space-8   32px
space-10  40px
space-12  48px
```

Рекомендуемый layout:

- sidebar: 240–264px;
- максимальная ширина контента: 1200–1280px;
- desktop padding: 32–48px;
- tablet padding: 24px;
- mobile padding: 16px;
- расстояние между секциями: 32–48px;
- расстояние внутри плотных рядов: 12–16px.

## 5. Формы, границы и поверхности

### Радиусы

```text
radius-sm  4px   поля и небольшие control
radius-md  8px   кнопки, input, dropdown
radius-lg  12px  стандартные контентные блоки
radius-xl  16px  крупные панели и overlay
```

В обновлённом визуальном направлении предпочтительны `radius-sm` и `radius-md`. Большие скруглённые карточки не должны использоваться повсеместно.

### Границы

- стандартная граница: 1px `border`;
- разделитель между секциями: `Separator`;
- акцентная линия прогресса: 3–4px `yellow-400`;
- не использовать толстый левый border как основной паттерн рекомендации.

### Тени

Тени только для интерактивных поверхностей и overlay:

```text
shadow-card   0 2px 8px rgba(18, 60, 52, 0.06)
shadow-hover  0 8px 24px rgba(18, 60, 52, 0.10)
shadow-modal  0 16px 40px rgba(18, 60, 52, 0.16)
```

Основной контент строится на фоне, типографике и разделителях, а не на множестве floating cards.

## 7. Соответствие shadcn/ui

Использовать уже установленные primitives из `src/shared/components/ui`:

| UX-задача | Компонент |
|---|---|
| Основное действие | `Button` |
| Статус или небольшой label | `Badge` |
| Поверхность сложного блока | `Card` с полной композицией |
| Прогресс | `Progress` |
| Разделитель | `Separator` |
| Навигация | `Sidebar`, `Tabs`, `Breadcrumb` |
| Таблица HR | `Table` |
| Фильтры | `Select`, `Popover`, `Checkbox` |
| Подробности активности | `Dialog`, `Sheet` |
| Загрузка | `Skeleton` |
| Ошибка | `Alert` |
| Пустое состояние | `Empty` |
| Уведомление | `Sonner` |

Бизнес-смысл остаётся в модуле `career-quest`, а primitives — в `shared/components/ui`.

## 8. Анимации и motion

Анимация должна объяснять изменение состояния, а не создавать игровую атмосферу.

| Сценарий | Duration | Поведение |
|---|---:|---|
| hover/focus | 120–180ms | изменение цвета или underline |
| раскрытие детали | 180–240ms | fade + короткий slide |
| переход страницы | 200–300ms | мягкий fade |
| обновление прогресса | 500–700ms | заполнение progress bar |
| skeleton | по умолчанию shadcn | без самодельных pulse-блоков |

Использовать easing `cubic-bezier(0.2, 0.8, 0.2, 1)`.

### Обязательная последовательность после выполнения

```text
Button → disabled/loading
  ↓
Progress bar плавно обновляется
  ↓
Skill level получает короткий highlight
  ↓
Появляется toast «Прогресс обновлён»
  ↓
Показывается следующий шаг
```

### Не использовать

- постоянное вращение и мигание;
- конфетти после каждой активности;
- bounce-анимации интерфейсных элементов;
- анимированный фон;
- декоративные AI sparkle-эффекты;
- переходы дольше 700–800ms.

Для пользователей с `prefers-reduced-motion: reduce` все необязательные transitions должны отключаться или сокращаться.

## 9. Состояния компонентов

Каждый ключевой компонент должен иметь состояния:

```text
default
hover
focus-visible
active
disabled
loading
success
error
empty
```

### Recommendation section

- `loading`: Skeleton для заголовка, объяснения и действия;
- `default`: одна основная рекомендация;
- `empty`: спокойное сообщение «Пока нет подходящего следующего шага»;
- `success`: обновлённый навык и новый процент готовности;
- `error`: Alert с возможностью повторить расчёт.

## 10. Приоритет визуальной иерархии

Порядок внимания на главной странице:

1. текущий грейд и прогресс к следующему;
2. один главный следующий шаг;
3. причина и ожидаемый результат;
4. ключевые skill gaps;
5. история и вторичная статистика.

Если пользователь видит больше одного равноценного CTA, иерархия нарушена.

## 11. Do / Don't

### Do

- использовать один основной CTA на экран;
- объяснять рекомендацию простым текстом;
- показывать разницу «сейчас / требуется / что изменится»;
- использовать зелёный для роста и жёлтый для цели;
- сохранять много воздуха и тонкие разделители;
- показывать HR агрегаты без публичных рейтингов.

### Don't

- превращать интерфейс в игровую таблицу лидеров;
- выделять каждую секцию отдельной floating-карточкой;
- использовать градиент и glow как доказательство AI;
- показывать рекомендацию без причины;
- смешивать employee view и HR view;
- использовать красный для обычного skill gap;
- добавлять декоративные элементы, которые не ведут к действию.

## 12. Критерий готовности UI

Пользователь должен пройти сценарий без объяснений разработчика:

```text
Вход → понять текущий грейд → увидеть главный разрыв → открыть следующий шаг
→ понять причину → выполнить активность → увидеть обновлённый прогресс
```

UI считается готовым, если визуальная система усиливает этот путь и не конкурирует с ним.
