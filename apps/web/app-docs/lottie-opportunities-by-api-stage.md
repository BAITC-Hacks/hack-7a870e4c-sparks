# Career Quest — дополнительные точки для Lottie по стадиям API

Этот документ дополняет [план API-интеграции](./api-implementation-stages.md) и
[правила motion](./interaction-and-motion.md). Он предлагает места для анимации,
но не добавляет требований к API, экранов или готовых ассетов. Состав блоков и
доступность маршрутов сверять с [композицией экранов](./screen-composition.md).

## Что уже предусмотрено

- На `/login` уже используется `LoginIllustration` с файлом
  `public/animations/career-quest-login.json` и статичной SVG-заменой.
- В `interaction-and-motion.md` уже описаны `ProgressSuccess` после завершения
  активности, `NoRecommendation` для пустых рекомендаций, `ImportSuccess` после
  импорта и общая иллюстрация `ErrorState`.
- Остальные идеи ниже — предложения для следующих стадий, а не реализованные
  функции. Файлы Lottie для них пока не заявлены как существующие.

## Где добавить анимацию

| Стадия API | Место и точное условие | Смысл и вариант композиции | Приоритет |
| --- | --- | --- | --- |
| 2–3: профиль и карьерный план | `/employee/career`, `goal_source=none` или нет целевой роли и `readiness=null` | `ChooseGoal`: коротко выстраивается незавершённая линия маршрута рядом с текстом «Укажите карьерную цель» и действием перехода к цели. Не изображать рассчитанный прогресс. Подходит и для Lead без автоматического следующего грейда. | P1 |
| 3: AI-советник | Блок диалога на `/employee/career`, запрос `POST /api/employees/{id}/chat` действительно отправлен и ответа ещё нет | `AdvisorThinking`: короткая однократная композиция из 2–3 спокойных кадров у ожидаемого ответа. Рядом остаются текст «Готовим ответ» и доступное состояние загрузки; затем можно оставить статичный кадр. Не использовать «AI sparkle» и не обещать ответ раньше API. | P2 |
| 5: HR overview | `/hr`, агрегаты успешно загружены, но `total_employees=0` | `EmptyDataset`: короткая иллюстрация пустой папки/набора данных возле CTA импорта. Показывать только HR; это состояние отсутствия данных, а не ошибка запроса. | P1 |
| 6: импорт | `/import`, локальная проверка выбранных файлов завершилась без ошибок и открыт preview, до `POST /api/hr/import` | `FilesReady`: одноразовое появление одного или двух файлов с галочкой возле preview. Подпись «Файлы готовы к отправке»; нельзя показывать «Импорт завершён», пока API не ответил успехом. | P2 |
| 6: импорт | `/import`, API вернул ошибку `400` или `413` после отправки | Вместо новой универсальной анимации можно повторно использовать `ErrorState` из motion-документа возле конкретного `message`/лимита. Ошибка должна оставаться читаемой, а файлы — доступными для исправления. | P2 |

### Важные границы состояний

- Для `mode=rules` не показывать `AdvisorThinking` или другие признаки работы AI
  в блоке рекомендаций: режим и `message` должны соответствовать ответу API.
- `ChooseGoal` не должен подменять `warnings`, `uncovered_skills` и объяснение
  отсутствия следующего грейда. Если план уже содержит цель, этот ассет не нужен.
- `EmptyDataset` показывать только после успешного ответа HR API. При `401`,
  `403`, `503` и сетевой ошибке нужны соответствующие текстовые состояния.
- `FilesReady` подтверждает лишь локальную проверку формата и размера. Полная
  атомарная валидация остаётся за backend; `ImportSuccess` показывается только
  после успешного `POST /api/hr/import`.
- При `already_completed=true` не запускать `ProgressSuccess` повторно и не
  изображать новый прирост навыка.

## Порядок внедрения

1. Сначала завершить основной API-сценарий и текстовые loading/empty/error/success
   состояния стадий 1–7.
2. Из новых ассетов первым добавить `ChooseGoal`: это заметное состояние для
   сотрудника без цели и Lead без следующего грейда. Затем `EmptyDataset` для
   первого HR-сценария без загруженных данных.
3. `AdvisorThinking` и `FilesReady` добавлять только после проверки, что они
   улучшают понимание ожидания и локальной проверки. Обычные spinner, skeleton,
   progress bar, hover и переходы оставить за CSS/shadcn.

На MVP действует правило: не больше одной смысловой Lottie одновременно на
экране. Если на том же экране уже есть `NoRecommendation` или `ImportSuccess`,
дополнительная анимация не запускается.

## Правила для реализации и проверки

- Использовать общий клиентский компонент-обёртку из
  `interaction-and-motion.md`; ассеты загружать по необходимости, а место под
  них резервировать заранее. Существующий `LoginIllustration` — отдельная
  текущая реализация, которую можно унифицировать при работе над обёрткой.
- У каждого состояния должен оставаться текст и доступное действие без JSON,
  JavaScript и при `prefers-reduced-motion: reduce`. Для reduced motion показать
  статичный кадр, SVG или только текст. Декоративной анимации задать
  `aria-hidden="true"`; не двигать фокус после завершения.
- Проигрывать короткие композиции один раз; ожидание API не должно зависеть от
  длительности анимации. Не задерживать ответ UI ради проигрывания Lottie.
- Перед добавлением внешнего ассета зафиксировать источник, версию и условия
  использования в `docs/external-materials.md`. Синтетические данные профилей
  не включать в JSON-анимации.
- Проверить каждый триггер на данных API: отсутствие цели, пустой HR-набор,
  успешный локальный preview, успешный импорт и ошибки `400`/`413`. Отдельно
  проверить reduced motion и мобильную ширину. Оценивать время ответа UI и вес
  ассетов после добавления, чтобы motion не мешал требованиям кейса.
