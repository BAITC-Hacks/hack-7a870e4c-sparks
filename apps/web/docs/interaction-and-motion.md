# Career Quest — интерактивность и motion

Документ описывает, как оживлять интерфейс Career Quest без превращения
корпоративного продукта в игровую механику. Motion должен объяснять изменение
состояния, направлять внимание и подтверждать результат действия.

Общие визуальные токены и базовые ограничения motion описаны в
[`ui-system-map.md`](./ui-system-map.md), а композиция экранов — в
[`screen-composition.md`](./screen-composition.md).

## 1. Основной принцип

Каждая анимация должна отвечать хотя бы на один вопрос:

- что изменилось;
- что сейчас происходит;
- куда переместилось внимание;
- можно ли продолжить действие;
- успешно ли завершилась операция.

Если анимация не помогает понять состояние или действие, она не нужна.

Приоритет:

```text
feedback действия → объяснение изменения → навигация → декоративный эффект
```

Декоративные эффекты имеют самый низкий приоритет и не должны появляться в
критическом пользовательском пути.

## 2. Когда использовать Lottie

В проекте уже установлен `lottie-react`. Lottie использовать для коротких,
законченных визуальных моментов, где SVG/CSS-анимация будет слишком сложной или
невыразительной.

### Подходящие сценарии

| Сценарий | Где | Роль Lottie |
|---|---|---|
| Успешное обновление прогресса | Activity Result | короткое подтверждение результата |
| Пустое состояние без рекомендации | Employee Dashboard | спокойная иллюстрация, не блокирующая CTA |
| Успешный импорт данных | Import | подтверждение завершения загрузки |
| Ошибка загрузки/импорта | Error state | мягкая иллюстрация рядом с текстом ошибки |
| Первый вход в продукт | Login | небольшая статичная или почти статичная иллюстрация |

### Не использовать Lottie

- для обычных hover и focus;
- для каждого появления карточки;
- вместо `Skeleton` во время загрузки данных;
- для постоянного движения на Dashboard;
- для навигационных переходов между страницами;
- для progress bar, badge и статусов, которые лучше объясняются CSS;
- для имитации «AI sparkle» или постоянного свечения;
- для конфетти после каждой активности.

Одна смысловая Lottie-анимация на экран — максимум для MVP. На основном
Employee Dashboard она не должна конкурировать с рекомендацией.

## 3. Матрица интерактивности MVP

| Элемент | Interaction | Реализация | Feedback |
|---|---|---|---|
| Primary Button | hover/focus/press | shadcn `Button` + CSS transition | изменение цвета, disabled/loading |
| Recommendation Card | открыть детали | link/route | переход на Activity Details |
| Progress Bar | обновление после активности | CSS width transition | 500–700ms, затем highlight |
| Skill Level | увеличение уровня | CSS highlight | короткое изменение фона/outline |
| Activity Action | запуск | mutation state | `Spinner`, disabled button |
| Activity Result | показать итог | inline reveal | before/after + toast |
| HR Filter | изменение фильтра | URL state через `nuqs` | обновление таблицы/графика |
| Employee Row | открыть детали | controlled `Sheet` | URL-driven open/Back |
| File Upload | drag/drop/select | input + dropzone state | preview, validation, error |
| Import Result | завершение импорта | Lottie по желанию | success state + переход в HR |

## 4. Основной motion flow активности

Для главного demo-сценария использовать одну последовательность:

```text
Нажатие «Начать активность»
  ↓ 120–180ms
Кнопка disabled + Spinner
  ↓ после успешного результата
ProgressBar обновляется за 500–700ms
  ↓ параллельно
изменившийся SkillLevel получает короткий highlight
  ↓
показывается toast «Прогресс обновлён»
  ↓ 180–240ms
открывается NextStepCard
```

Lottie для success можно показывать рядом с `ResultHeader` после обновления
прогресса. Она должна проигрываться один раз и не скрывать before/after
значения.

## 5. Рекомендованные Lottie-композиции

### `ProgressSuccess`

- назначение: подтверждение завершения активности;
- размер: 64–96px рядом с заголовком результата;
- воспроизведение: один раз;
- loop: `false`;
- autoplay: только после успешного результата;
- не использовать как единственный способ сообщить об успехе.

### `NoRecommendation`

- назначение: пустое состояние рекомендаций;
- размер: до 180px desktop, до 140px mobile;
- loop: допустим только очень медленный и ненавязчивый loop;
- autoplay: допустим;
- рядом обязательно должен быть понятный текст и следующий доступный action.

### `ImportSuccess`

- назначение: подтверждение валидного импорта;
- размер: 72–120px;
- воспроизведение: один раз после завершения операции;
- после анимации остаются summary и ссылка в `/hr`.

### `ErrorState`

- назначение: визуальное сопровождение ошибки;
- предпочтительно: статичный кадр или очень короткая анимация;
- loop и bounce не использовать;
- основной акцент остаётся на тексте ошибки и кнопке `Повторить`.

## 6. Технические правила Lottie

### Assets

Файлы хранить в отдельной директории:

```text
apps/web/public/animations/
├── progress-success.json
├── no-recommendation.json
├── import-success.json
└── error-state.json
```

Названия должны описывать сценарий, а не автора или источник файла.

### Компонентная обёртка

Не импортировать `lottie-react` напрямую в бизнес-компонентах. Использовать
общую обёртку, например:

```text
shared/components/animation/LottieAnimation.tsx
```

Обёртка отвечает за:

- `aria-hidden` для декоративных анимаций;
- `prefers-reduced-motion`;
- размеры и responsive constraints;
- `autoplay`, `loop`, `speed`;
- fallback без JavaScript или при ошибке загрузки;
- lazy loading для неважных анимаций.

Бизнес-модули передают только имя сценария и параметры отображения:

```tsx
<LottieAnimation name="progress-success" decorative />
```

### Client component

Так как `lottie-react` использует browser APIs, компонент-обёртка должен быть
клиентским компонентом. Server-side страницы не должны напрямую создавать
Lottie instance.

### Производительность

- не загружать все JSON-файлы на каждом экране;
- использовать dynamic import или lazy loading для вторичных анимаций;
- не использовать большие растровые изображения внутри Lottie;
- держать композиции короткими и небольшими по размеру;
- проверять мобильный Lighthouse/performance после добавления assets;
- не блокировать отображение основного контента ожиданием анимации.

## 7. Accessibility

Анимация не должна быть единственным носителем смысла.

Обязательно:

- текстовый success/error feedback остаётся на экране;
- декоративная Lottie имеет `aria-hidden="true"`;
- смысловая анимация сопровождается доступным текстом;
- для `prefers-reduced-motion: reduce` autoplay отключается, loop отключается,
  а важный результат показывается статичным состоянием;
- focus не должен перемещаться из-за окончания анимации;
- анимация не должна мигать или быстро менять контрастные цвета.

Минимальный reduced-motion fallback:

```text
ProgressSuccess → статичная success-иконка или вообще без иллюстрации
NoRecommendation → статичная иллюстрация
ImportSuccess → статичная success-иконка
ErrorState → статичная иллюстрация
```

## 8. Правила интерактивных состояний

### Buttons

- hover: только цвет/контраст, 120–180ms;
- focus-visible: заметный ring;
- pressed: краткое изменение поверхности;
- loading: Spinner + disabled;
- не менять ширину кнопки при появлении Spinner.

### Cards

- карточка не должна полностью «прыгать» при hover;
- hover допустим только для кликабельной карточки;
- использовать лёгкое изменение border/shadow;
- не применять постоянное scale увеличение.

### раскрытия и overlays

- детали рекомендации открываются переходом на маршрут;
- employee details открываются через controlled `Sheet`;
- Dialog/Sheet должен иметь доступный title;
- закрытие через Back должно работать, если overlay отражён в URL.

## 9. Storybook coverage

Для motion и интерактивности нужны отдельные stories:

- `Button/Loading`;
- `ProgressSummary/Updating`;
- `RecommendationCard/Default`;
- `RecommendationCard/Empty`;
- `RecommendationCard/Error`;
- `ActivityResult/Success`;
- `LottieAnimation/ProgressSuccess`;
- `LottieAnimation/ReducedMotion`;
- `Import/Validating`;
- `Import/Invalid`;
- `Import/Success`.

В stories должен быть способ проверить состояние без ожидания реального API.

## 10. Definition of done

Интерактивный экран готов, если:

- каждое действие имеет понятный feedback;
- loading/error/success состояния не зависят от Lottie;
- Lottie используется только там, где усиливает смысл состояния;
- есть reduced-motion fallback;
- нет layout shift при загрузке animation asset;
- анимации не блокируют основной контент;
- ключевые состояния покрыты Storybook;
- основной flow можно пройти с отключённой анимацией.
