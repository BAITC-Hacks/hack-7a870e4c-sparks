# Career Quest API

API кейса 1 HackAlem AI на Elysia.js, Bun и Prisma с PostgreSQL, связанный с [Python-агентом](../agent/README.md) на FastAPI. Сотрудник видит собственный профиль, выбирает карьерную цель, получает объяснимые шаги развития и карьерный план, обсуждает их с консультантом и подтверждает выполнение. HR видит сводку дефицитов, открывает профили и импортирует дополнительные синтетические JSON/CSV-данные.

## Стек и структура

- Bun 1.3.14+, Elysia 1.4.30, TypeScript 5.9.3.
- PostgreSQL 17, Prisma Client/CLI и `@prisma/adapter-pg` 7.10.0, драйвер `pg` 8.23.0.
- `@elysiajs/openapi` 1.4.16 и `csv-parse` 7.0.2.
- Python 3.12, FastAPI и OpenAI Responses API со Structured Outputs — в отдельном `apps/agent`. Только Python-агент обращается к OpenAI; в Compose модель по умолчанию — `gpt-4.1-mini`.

Сохранена структура исходного API-шаблона:

```text
src/index.ts                 запуск, загрузка данных и аккаунтов
src/app.ts                   сборка модулей Elysia
src/contracts.ts             общие доменные типы
src/modules/auth/            вход, сессии, проверка прав
src/modules/employees/       профиль, цель, навыки и завершение активностей
src/modules/recommendations/ клиент Python-агента, план, чат и резервный подбор
src/modules/hr/              HR-сводка и импорт
src/modules/catalog/         навыки и требования ролей
src/utils/dataset/index.ts   загрузка и проверка JSON/CSV
src/utils/db/index.ts        Prisma-хранилище и транзакции
src/utils/config/index.ts    переменные окружения
src/utils/http/              общие ошибки и HTTP-модели
src/plugins/openapi.ts       публикация OpenAPI
prisma/schema.prisma         модели Prisma
prisma/migrations/           SQL-миграции
generated/client/            генерируемый Prisma Client
tests/                       доменные, HTTP, Prisma и AI-тесты
openapi.json                 экспортированный контракт
```

У HTTP-модулей используются файлы `index.ts`, `controller.ts`, `service.ts` и `model.ts`. Неиспользуемые утилиты исходного шаблона, модели `User`/`UserRole` и три старые миграции удалены. Схема содержит только сущности Career Quest; для новой БД сохранена одна начальная миграция `20260923000100_career_init`.

Очистка файлов миграций рассчитана на новую БД. Она не удаляет ранее примененные миграции, таблицы или данные в существующих БД.

## Запуск

API, PostgreSQL и Python-агент запускаются из корня репозитория командой `./init.sh`. Скрипт добавляет недостающие пароли в `.env`, собирает Docker-образы, ждет готовности сервисов и на macOS открывает Swagger. Существующие настройки и данные сохраняются. Для запуска без браузера: `./init.sh --no-open`; для остановки: `docker compose down`. Нужны работающий Docker, Compose с `--wait` и `openssl`. Пароли `hr` и сотрудника `E0005` находятся в корневом `.env`; порт задается через `API_PORT` (по умолчанию 3001).

Образ устанавливает зависимости через `bun install --frozen-lockfile --production`, генерирует Prisma Client и OpenAPI JSON. Prisma CLI входит в рабочие зависимости, поскольку применяет миграции при запуске контейнера. Сервер работает от пользователя `bun`. PostgreSQL и агент не публикуют порты на хосте. API обращается к агенту по `http://agent:8000` во внутренней сети Compose и запускается после успешных healthcheck обоих сервисов.

Для отдельного API нужны Bun и доступный PostgreSQL. Отдельно запустите [Python-агент](../agent/README.md#локальный-запуск-агента); его адрес задается через `AGENT_URL` (по умолчанию `http://127.0.0.1:8000`). В каталоге `apps/api` создайте `.env` по [.env.example](.env.example), задайте `DATABASE_URL`, `HR_PASSWORD` и `CREDENTIAL_SECRET`. Для демонстрационного сотрудника можно задать отдельный `DEMO_EMPLOYEE_PASSWORD`. Выполните:

```bash
bun install --frozen-lockfile
bun run generate
bun run migrate:deploy
bun run start
```

Для автоматического перезапуска при изменениях вместо `start` используйте `bun run dev`. Миграции применяются до запуска сервера; загрузка исходного набора происходит только в пустую БД. Повторный запуск сохраняет цели, историю и импорт. Сервер по умолчанию слушает `127.0.0.1:3001`.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Подключение к PostgreSQL: `postgresql://USER:PASSWORD@HOST:5432/DATABASE?schema=public` |
| `API_PORT`, `API_HOST` | Порт и интерфейс API; по умолчанию `3001`, `127.0.0.1` |
| `DATASET_PATH` | Путь к исходному набору; по умолчанию `case_1/career_quest_dataset` этого репозитория |
| `HR_PASSWORD` | Начальный пароль аккаунта `hr`, минимум 12 символов |
| `CREDENTIAL_SECRET` | Секрет начальных индивидуальных паролей сотрудников, минимум 32 символа |
| `DEMO_EMPLOYEE_ID` | Демонстрационный сотрудник; по умолчанию `E0005` |
| `DEMO_EMPLOYEE_PASSWORD` | Необязательный отдельный пароль демонстрационного сотрудника, минимум 12 символов |
| `APP_ORIGIN` | Разрешенный origin интерфейса; по умолчанию `http://localhost:3000` |
| `COOKIE_SECURE` | `true` для HTTPS, `false` для локального HTTP |
| `AGENT_URL` | HTTP(S)-адрес Python-агента без пути и учетных данных; локально `http://127.0.0.1:8000`, в Compose `http://agent:8000` |
| `TEST_DATABASE_URL` | Отдельная тестовая PostgreSQL БД для интеграционных тестов |

Bun читает локальный `.env`; секреты не входят в Git. `OPENAI_API_KEY` и `OPENAI_MODEL` задаются для Python-агента: при запуске Compose — в корневом `.env`. Compose передает их только агенту, API ключ не получает. Без ключа агент возвращает рекомендации по правилам. Изменение начальных паролей в конфигурации не меняет уже созданные аккаунты. Получить индивидуальный доступ к существующему синтетическому профилю можно приватно командой `bun run credentials:employee E0003`; она проверяет согласованность текущего секрета с сохраненным хешем. Импорт не выдает пароль автоматически.

## OpenAPI JSON

- [JSON-контракт](http://localhost:3001/api/openapi.json): `GET /api/openapi.json`.
- [Swagger UI](http://localhost:3001/api/docs): `GET /api/docs`.
- Файл контракта: [openapi.json](openapi.json).

Схема строится из Elysia-моделей запросов и ответов. В ней описаны параметры, ошибки, стабильные `operationId` и cookie `career_quest_session`. После изменения маршрутов экспортируйте актуальную версию:

```bash
bun run generate
bun run openapi
```

Для интеграции интерфейса используйте `apps/api/openapi.json` в конфигурации генератора клиента. Текущий `apps/web` — исходный frontend-шаблон; его подключение к этому API не входит в выполненные проверки.

Список маршрутов и семантика ответов: [контракт API](../../docs/api-contract.md). После `POST /api/auth/login` клиент сохраняет cookie и отправляет ее с последующими запросами. Документация и `/api/health` доступны без авторизации; чтение профилей, каталог и операции развития требуют сессии.

## План, рекомендации и чат

Все три маршрута требуют сессию и разрешают сотруднику обращаться только к своему ID; HR может открыть доступный ему профиль. API собирает контекст из PostgreSQL: исходную оценку навыков, выбранную цель, каталоги и историю только запрошенного сотрудника. Клиент не передает профиль или каталоги в запросах к этим маршрутам.

| Маршрут | Запрос и результат |
| --- | --- |
| `POST /api/employees/{id}/recommendations` | Тело `{}`; до трех карточек с факторами и объяснением, `mode`, `model`, `message`, `generated_at`, `duration_ms` |
| `GET /api/employees/{id}/plan` | План с эффективными и прогнозируемыми навыками, разрывами, траекторией, рекомендациями и предупреждениями; OpenAI не вызывается |
| `POST /api/employees/{id}/chat` | `message` и необязательный `conversation_history`; ответ содержит `employee_id`, `reply`, `plan` и полный результат `recommendations` |

Пример тела чата:

```json
{
  "message": "Какие навыки мне развивать для следующего грейда?",
  "conversation_history": []
}
```

Сообщение и каждая реплика ограничены 3000 символами. История содержит до 20 элементов `{ "role": "user" | "assistant", "content": "..." }`; модель получает последние 12. Историю диалога должен сохранять клиент и передавать при следующем запросе.

API ограничивает ожидание ответа агента 9 секундами, включая чтение тела, и проверяет схему ответа, доступность мероприятий и факторы. При недоступности агента, таймауте или некорректном ответе `recommendations` возвращает HTTP 200 с локальным подбором API и `mode: "rules"`; `plan` и `chat` возвращают HTTP 503 с сообщением. Если сам агент доступен, но OpenAI не настроен или не ответил, рекомендации и чат возвращаются из агента в расчетном режиме.

`GET /api/health` проверяет PostgreSQL и `/health` агента (таймаут 1 секунда). Поле `agent_available` показывает доступность агента, `ai_configured` — наличие настроенного ключа по его ответу. Наличие ключа не подтверждает доступ к модели. Если агент недоступен, API с рабочей БД сохраняет HTTP 200 и `status: "ok"`, оба флага равны `false`.

## Воспроизводимая проверка

1. Проверьте `GET /api/health`: при работающем агенте без ключа ожидается `{ "status": "ok", "agent_available": true, "ai_configured": false }`.
2. Войдите сотрудником `E0005`, используя локально выданный пароль. Запросите `GET /api/employees/E0005`, `GET /api/employees/E0005/plan`, `POST /api/employees/E0005/recommendations` с `{}` и `POST /api/employees/E0005/chat` с примером выше. Без ключа рекомендации и чат должны иметь `mode: "rules"`.
3. Возьмите `event.event_id` из допустимой рекомендации и вызовите `POST /api/employees/E0005/activities/{eventId}/complete`. Повторно загрузите профиль и план: новое завершение учтено в эффективных навыках, если его день строго позже последней оценки. Повторный запрос завершения должен вернуть `already_completed: true` без повторного прироста.
4. Убедитесь, что сотрудник получает 403 при запросе другого профиля или `/api/hr/overview`. Войдите HR и повторите разрешенные HR-запросы.
5. Через HR импортируйте содержимое [примеров жюри](../../examples/jury/) строками `employees_json` и `history_csv`. Проверьте новый ID. Ошибка в одном из файлов должна отменять весь импорт.
6. Перезапустите API и убедитесь, что измененные данные сохранились.

Проверки кода:

```bash
bun run typecheck
bun test tests/domain.test.ts tests/recommendations.test.ts
```

Полный прогон требует отдельной PostgreSQL БД, указанной в `TEST_DATABASE_URL`, и права создавать в ней схемы:

```bash
TEST_DATABASE_URL='postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:5432/career_quest_test?schema=public' bun run test
```

Интеграционные тесты создают уникальные схемы, применяют миграции и удаляют только свои схемы после завершения. Используйте отдельную тестовую БД. Тесты ошибок и ответов AI подменяют HTTP-транспорт и не делают платных запросов.

Для сквозной проверки API → FastAPI запустите отдельный агент без ключа (из корня репозитория):

```bash
OPENAI_API_KEY='' OPENAI_KEY='' venv/bin/uvicorn agent.main:app --app-dir apps --host 127.0.0.1 --port 8000
```

Затем в `apps/api`, задав `TEST_DATABASE_URL`, выполните:

```bash
TEST_AGENT_URL=http://127.0.0.1:8000 bun run test
```

Без `TEST_AGENT_URL` четыре сквозных теста пропускаются. Они проверяют реальную связь с агентом, план и чат, обновление навыков после завершения и импорт профилей жюри.

Проверено при интеграции: TypeScript, 76 тестов API с PostgreSQL и работающим FastAPI, 15 Python-тестов, экспорт OpenAPI (14 путей). Проверены планы и рекомендации для всех 200 исходных профилей. Отдельный Docker Compose прошел сборку, healthcheck и HTTP-сценарий вход → план/рекомендации/чат → завершение → обновленный план; повторное завершение не начисляет прирост. Все проверки выполнены без живых обращений к OpenAI.

## Правила и ограничения

Расчеты используют `meta.as_of_date` (`2026-10-01` в исходном наборе), а не текущую дату. Отсутствующий навык равен 0. `employee.skills` остается снимком на `last_review_date`; прирост вычисляется отдельно в `effective_skills`. Учитываются только завершения с известным `completed_at`, день которого строго позже дня последней оценки и не позже даты среза. Исходная история без точной даты завершения сохраняется, но не добавляет навыки; дата участия не подставляется вместо `completed_at`. Завершение в демонстрационном API получает время `as_of_dateT12:00:00.000Z`. Импорт принимает необязательную колонку `completed_at` в формате UTC `YYYY-MM-DDTHH:mm:ss.sssZ`. Повторный расчет не накапливает прирост, а `max_level` никогда не снижает уже достигнутый навык. Требования выбранной цели и доступность каталога определяются серверным кодом. Обязательные мероприятия не рекомендуются, но их история сохраняется. Подробнее: [политика данных](../../docs/data-policy.md).

Python-агент передает OpenAI карьерные факты, до 12 допустимых кандидатов, до 24 последних записей участия и последние 12 реплик чата. Имя и ID сотрудника из профиля исключаются; текст переписки передается как получен. Запрос выполняется с `store: false`. Агент проверяет выбор 1–3 уникальных мероприятий, критический приоритет и последовательную пользу шагов; факторы и объяснения вычисляет код. Если допустимых шагов нет, список пуст. Таймаут попытки OpenAI — 8 секунд без повторного запроса; ошибка, отказ или невалидный выбор включают расчетный режим агента. Предел ожидания агента на стороне API — 9 секунд. Живая интеграция OpenAI и качество выбора внешней модели не подтверждаются тестами с подменой транспорта.

Покрытие требований не означает автоматическое повышение. Подтверждение выполнения — демонстрационный сценарий без LMS-интеграции. PostgreSQL хранит состояние в отдельном volume `career_postgres_data`; автоматического переноса прежней SQLite-БД нет. Публичное production-развертывание выполняет пользователь; URL пока не предоставлен. Происхождение и лицензии материалов: [реестр](../../docs/external-materials.md).
